# つみきそうじ（Mac の掃除）

拭いているあいだ、キー・メディアキー（音量・明るさ）・トラックパッド・マウスを効かなくするメニューバー常駐アプリ。
画面は夜の帳面の色で覆い（汚れが見やすい）、真ん中に残り時間と、長押しの輪だけを出す。
Claude・tmux・つみきリモートなど、中で動いているものはそのまま動く（止めるのは手元の入力だけ）。

## 解除（3つ＋アプリが終われば戻る）
1. **クリック（どのボタンでも）を3秒押し続ける**。輪が一周すると外れる。ボタンごとに数え、どれか1つでも押しているあいだは続く。
   拭いていてトラックパッドを3秒押しっぱなしにすると外れる（割り切り）。マウスもトラックパッドも無い Mac は時間待ちだけ
2. **時間で自動解除**：メニューバーで 1・2・3・5・10分（既定2分）。設定ファイルを書き換えても10分を超えない
3. **見張り**：自動解除の時刻から3秒たっても掃除が続いていたら、別の糸がアプリごと終わらせる（`_exit`＝後始末を待たない）
4. 入力を捨てる口（CGEventTap）はこのアプリの中だけ＝**アプリが終われば（落ちても・`pkill TsumikiClean` でも）入力は戻る**。
   掃除の状態は保存しないので、落ちて起き直しても掃除の続きにはならない

## 使い方
- 開くとすぐ始まる（メニュー「開いたら始める」で切れる）。動いているときにもう一度開いても始まる
- メニューバー：始める／1分〜10分／開いたら始める／（許可が無いときだけ）許可…／終了
- ログイン時に開かれたとき・Mac が起きて3分以内に開かれたとき（再起動後の復元など）は始めない
- 掃除中に画面を抜き差ししたら、幕を掛け直す
- 許可があるのに口を作れなかったときは、音を鳴らして始めない
- 初回は「アクセシビリティ」の許可が要る。許可が無いときは macOS の確認を出し、2分のあいだに許可されたらそのまま始める

## 止めるもの・止めないもの
| もの | 止まるか |
|---|---|
| キー・修飾キー・F キー | 止まる（試験で確認：F19） |
| 音量・明るさ・キーボードの明かり（NX_SYSDEFINED） | 止まる（試験で確認：明かりの切り替え） |
| クリック・移動・ドラッグ・スクロール | 止まる（試験で確認：移動・スクロール・10番ボタン） |
| 3本指のスワイプ・拡大・回転・強く押す | 口では受け取っている。**作り物の入力を作れないので、本当に止まるかは手で試していない** |
| Touch ID（電源）ボタン | **止めない**。短く押すと画面がロックされることがある。長押しの強制終了はどのアプリでも止められない |
| 「セキュアキーボード入力」中のキー | 未確認の弱点。ターミナルの「セキュアキーボード入力」などがオンだと、口にキーが来ない恐れ |

## 作り
| ファイル | 中身 |
|---|---|
| `main.swift` | メニュー・掃除の開始と解除・見張り・許可の待ち |
| `Core.swift` | 止める種類・時間・長押しの数え（純粋な決まりごと） |
| `Blocker.swift` | 入力を捨てる口（HID の段・先頭）。macOS に止められたらすぐ開け直す |
| `Curtain.swift` | 幕（全画面ごと・CGShieldingWindowLevel）。`--render out.png 幅 高さ 残り秒 長押し(0〜1)` |
| `Icon.swift` | アイコン（積み木ときらめき）をコードで描く。`--icons <フォルダ>` |
| `SelfTest.swift` | `--selftest`（許可なし・build.sh が毎回通す）と `--e2e <結果.txt>`（許可したアプリの中で本物の口に無害な入力を流して数える・15秒で必ず終わる） |

- 組み立て：`./build.sh` → 自己テスト → `~/Applications/つみき/TsumikiClean.app`（開発者証明書で署名＝組み直しても許可が外れない）
- 本物の口の試験：`open -W -n ~/Applications/つみき/TsumikiClean.app --args --e2e /tmp/e2e.txt`
- 短く本番を試す：`open -n ~/Applications/つみき/TsumikiClean.app --args --clean-for 8`（8秒で外れて終わる）
- 配る：`./notarize.sh <出力.zip>`（Developer ID で署名→公証→staple→spctl→ditto で `._` なし）。中身は `package.sh`（Apple シリコンと Intel の両方）
- 配布ページ：`~/tsumiki-tools/tsumiki-clean.html`・`tsumiki-clean.zip`・`icon-tsumiki-clean.png`

## App Store 版について（作っていない）
つみきショットの `appstore.sh`・`AppStore.entitlements`・`-D APPSTORE` の形には**そのままは乗らない見込み**。
入力を捨てる口（`.defaultTap`）にはアクセシビリティの許可が要り、箱の中（サンドボックス）では取れないか、
審査で外される恐れが高い（Apple の開発者フォーラムでも答えが割れている。のぞくだけの `.listenOnly`＋入力監視なら箱の中でも動く）。
乗せるなら、試しに箱の中で組んで許可が取れるかを先に確かめる。

## App Store 版の試し（2026-11-13・まだ出していない）
箱（サンドボックス：app-sandbox だけ）で組み、開発用の証明書で署名して確かめた。
- アクセシビリティの許可は**箱の中でも効く**（許可はアプリごと＝同じ ID・同じ署名の許可がそのまま使われた。ID を変えた版は許可なし＝口を作れない）
- 許可があれば、HID の段の「止める口」（defaultTap）も作れ、`--e2e`（キー・メディアキー・移動・スクロール・ボタンを捨てる・3秒押しで解除）は箱の中で全部 ✓。`--selftest` も ✓
- 未確認：App Store 版は Apple の署名になるので、入れた人がもう一度「アクセシビリティ」で入れる必要がある。許可を求める確認（プロンプト）が箱の中で出るかは試していない（設定を開いて入れてもらう流れは今のまま使える）
- 審査で「入力を止める」使い方が通るかは別の問題（出すかどうかは決めていない）
